# 2. gpt2权重可视化
## 2.1 wpe（位置嵌入）

**固定成正余弦函数 vs 随机初始化**
1. GPT-2 的 `wpe` 是随机初始化的（正态分布，std=0.02），并且是可学习的。初始化链路是这样的：
   1. `GPT2Model.__init__` 里创建 `self.wpe = nn.Embedding(...)` 后调用 `self.post_init()`（[modeling_gpt2.py:503](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gpt2/modeling_gpt2.py#L503) ）；
   2. `post_init()` 会递归地对每个子模块调用 `_init_weights`。GPT2 自己的 `_init_weights`（[modeling_gpt2.py:433](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gpt2/modeling_gpt2.py#L433)）先执行 `super()._init_weights(module)`，它只额外处理了 `Conv1D` 和注意力输出投影的缩放初始化，**没有覆盖** `nn.Embedding` 的处理；
   3. 因此 `wpe` 走的是基类逻辑（[modeling_utils.py:2321](https://github.com/huggingface/transformers/blob/main/src/transformers/models/modeling_utils.py#L2321)）：`init.normal_(module.weight, mean=0.0, std=std)`，其中 `std = config.initializer_range`，GPT2Config 默认值为 **0.02**（[configuration_gpt2.py:89](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gpt2/configuration_gpt2.py#L89)）。
   4. 所以：**是从 N(0, 0.02²) 随机采样初始化的可学习参数**，随预训练一起更新。这也意味着它是“学习的绝对位置嵌入”——预训练时模型自己学出每个位置的向量，而不是公式算出来的。当然，如果用 `from_pretrained("openai-community/gpt2")` 加载，`wpe` 会被 checkpoint 里的预训练值覆盖，随机初始化只影响从头训练的场景。
2. 原始论文用的是 sin/cos 位置编码——但严格说是“固定编码”，不是“初始化”。《Attention Is All You Need》中的正弦位置编码公式为：
   $$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right), \quad PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
   + 论文里的位置编码是**直接由公式确定、没有任何可学习参数**的固定向量，不进行训练，完全不更新。
   + 论文还做过对比实验：学习的位置嵌入和正弦编码效果基本相当，他们选正弦编码是希望对更长的序列有外推能力。
3. **两种方案的关系**：
   1. GPT/GPT-2 采用的是“学习的位置嵌入”路线（`wpe`，随机初始化 + 训练），而没有沿用 Transformer 原论文的固定正弦编码。
   2. transformers 里正弦编码的实现，可以参考 `SinusoidalPositionalEmbedding`，BART、Marian 等模型还在用它。

## 3.2 TensorFlow vs huggingface(pytorch)历史差异
**prompt**:

已知加载的gpt2模型权重有以下结构：
```bash
transformer.h.1.mlp.c_fc.weight torch.Size([768, 3072])
transformer.h.1.mlp.c_fc.bias torch.Size([3072])
transformer.h.1.mlp.c_proj.weight torch.Size([3072, 768])
transformer.h.1.mlp.c_proj.bias torch.Size([768])
```
但是根据 pytorch的nn.linear, weight.shape为(out_features,in_features),bias的shape为
(out_features)，是不是和上面显示的不一致啊

----

**回答**：

出现这种“不一致”的原因，主要源于**历史框架差异**以及 **Hugging Face 的兼容实现**。以下为您详细拆解背后的原因：
1. 历史原因：TensorFlow 与 PyTorch 的默认设定不同。GPT-2 最初是由 OpenAI 使用 **TensorFlow** 训练和发布的。
     - 在 TensorFlow 的 `tf.layers.dense` 或 `tf.keras.layers.Dense` 中，全连接层的权重默认形状是 `(in_features, out_features)`。
     - 而在 PyTorch 的 `nn.Linear` 中，为了优化矩阵乘法的内存访问，权重默认形状被设计为 `(out_features, in_features)`（即数学公式 $y = xW^T + b$ 中的 $W^T$ 的转置）。
2. Hugging Face 的兼容实现：自定义 `Conv1D`， 当 Hugging Face 的 `transformers` 库将 GPT-2 移植到 PyTorch 时，为了能够**直接、无缝地加载原始的 TensorFlow 权重**（避免在转换时做大量的转置操作），他们并没有直接使用 PyTorch 原生的 `nn.Linear`，而是实现了一个自定义的 `Conv1D` 类来模拟全连接层。
   + [transformers/src/transformers/models/gpt2/modeling_gpt2.py](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gpt2/modeling_gpt2.py)中，有`from ...pytorch_utils import Conv1D`
   + [transformers/src/transformers/pytorch_utils.py](https://github.com/huggingface/transformers/blob/main/src/transformers/pytorch_utils.py#L95)
    ```python
    class Conv1D(nn.Module):
        """
        1D-convolutional layer as defined by Radford et al. for OpenAI GPT (and hence used in GPT-2).
        """
        def __init__(self, nf, nx):
            super().__init__()
            self.nf = nf  # out_features
            self.nx = nx
            # 注意这里的初始化：形状是 (nx, nf) 即 (in_features, out_features)
            self.weight = nn.Parameter(torch.empty(nx, nf)) 
            self.bias = nn.Parameter(torch.zeros(nf))
            nn.init.normal_(self.weight, std=0.02)

        def forward(self, x):
            size_out = x.size()[:-1] + (self.nf,)
            # 核心计算：x @ weight + bias，而不是 nn.Linear 的 x @ weight.T + bias
            x = torch.addmm(self.bias, x.view(-1, x.size(-1)), self.weight)
            x = x.view(size_out)
            return x
    ```

**源码解析：**
- **权重初始化**：`torch.empty(nx, nf)` 明确指定了权重形状为 `(in_features, out_features)`，这与 TensorFlow 保持一致。
- **前向传播**：使用了 `torch.addmm(bias, x, weight)`，其数学本质是 $x \times weight + bias$。因为 $x$ 的最后一维是 `in_features`，`weight` 的形状是 `(in, out)`，所以矩阵乘法可以直接进行，最终输出维度为 `out_features`。这与 `nn.Linear` 中 $x \times weight^T + bias$ 的数学结果是完全等价的。

---
所以如果不想重写一个`Conv1D`, 可以直接把`nn.Linear`的(`in_features`, `out_features`)参数交换一下即可。

例如：以这层为例
```bash
transformer.h.1.mlp.c_fc.weight torch.Size([768, 3072])
transformer.h.1.mlp.c_fc.bias torch.Size([3072])
```
+ `Conv1d`
  + 定义是: `self.c_fc = Conv1D(4*embed_dim, embed_dim)`， 参考[src/transformers/models/gpt2/modeling_gpt2.py](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gpt2/modeling_gpt2.py#L636)
  + 执行的操作则是: $(*, nx)*(nx,nf) = (*, nf)$, `nx`是`in_features`, `nf`是`out_features`
  + 即： $(*,in)*(in,out) = (*, out)$, 
  + 定义是`Conv1D(out, in)`, 打印出来是`w = (in,out), bias = out`
+ `nn.Linear`
  + 正常定义是 `nn.Linear(in_features,out_features)`, 执行的操作是$x \times weight^T + bias$, 即$(*, in)*(in,out)=(*,out)$, 其实也就是多一个把`weight`转置的操作
  + 所以计算其实是一样的，但是传入参数的顺序以及`w`矩阵打印的形状不同
+ 假设这里要用`nn.Linear`来实现上面`Conv1d`的功能，
  + mlp的上一层是
    ```python
        self.ln_2 = nn.LayerNorm(config.n_embed)
        self.mlp = MLP(config)
        # 所以mlp的输入是(*, 768)
    ```
  + 则初始化就要变为: `nn.Linear(768, 3072)`, 则执行的操作就是: `(*,768)*(768,3072)= (*, 3072)`, 打印的`w = (3072, 768), bias = (3072)`
  + 只是打印出来的结果矩阵维度有些不同，但是实际执行的操作是一样的

$$
\begin{align}
loss = & -log(\frac{e^{\frac{1}{50257}}}{ e^{\frac{1}{50257}} + e^{\frac{1}{50257}} + ... + e^{\frac{1}{50257}}}) \\
     = & -log(\frac{e^{\frac{1}{50257}}}{50257*e^{\frac{1}{50257}}}) \\
     = & -log(\frac{1}{50257}) \\
     = & log(50257)\\
\end{align}
$$

## 4.1 pytorch的matrix vs tensor
+ <https://docs.pytorch.org/docs/2.14/generated/torch.matmul.html>中有：
  + `The first N-2 dimensions of each argument, the batch dimensions, are broadcast (and thus must be broadcastable). The last 2, the matrix dimensions, are handled as in the matrix-matrix product.`
    >[!NOTE]
    > 即：如果在进行矩阵相关的操作，但是输入的tensor维度大于2，则前`N-2`(减法)的维度都被认为是`batch`, 只有最后两个维度被认为是矩阵维度
+ 对于`torch.tril: Returns the lower triangular part of the matrix (2-D tensor) or batch of matrices input, the other elements of the result tensor out are set to 0.`
  + `Matrix`：在 PyTorch 中默认指代 2D Tensor（最后两维）。
  + `Batch of`：指代在 Matrix 前面附加的任意数量的维度（Batch 维度）。
  + `batch of matrices` 在 PyTorch 开发者的共识中，就等价于“最后两维是矩阵，前面是 Batch”。
+ **PyTorch 处理高维张量时的“全局通用约定”（Global Convention）**
  + **矩阵维度规则**：对于任何带有“矩阵”语义的操作（如 `tril`, `triu`, `matmul`, `bmm`, `det`, `inv`, `svd`, `eig` 等），**永远假设最后两个维度（dim=-2, dim=-1）是矩阵的行和列**。
  + **Batch 维度规则：前面的所有维度（dim=0 到 dim=-3）都是 Batch 维度**。操作会在这些 Batch 维度上独立、并行地进行（或者通过 Broadcasting 广播机制对齐）。

## 4.2 model.eval()什么时候发挥作用

**如果模型中绝对没有使用任何依赖 `self.training` 状态的模块（如 Dropout、BatchNorm 等），那么调用 `model.eval()` 和不调用，在前向传播的数学计算结果上是完全没有区别的。**
+  `model.eval()` 的本质
   + 在 PyTorch 中，`model.eval()` 的源码非常简单，它仅仅是递归地将模型中所有子模块的 `self.training` 属性从 `True` 修改为 `False`。
   - 对于 `BatchNorm`、`Dropout` 等模块，它们的 `forward` 函数内部会判断 `if self.training:`，从而在训练和推理时执行不同的逻辑。
   - 对于 `Linear`、`Conv2d`、`ReLU`、`LayerNorm`、`RMSNorm` 等绝大多数基础模块，它们的 `forward` 函数**根本不检查** `self.training` 状态，因此无论 `eval()` 还是 `train()`，计算逻辑完全一致。
   + 即：`BatchNorm`、`Dropout` 等模块需要`eval()`是因为有`self.training`这个参数的修改
+ 注意： - `model.eval()` **不会**关闭梯度计算（Autograd 引擎依然会构建计算图）。
  - 如果推理时只调用了 `model.eval()` 而没有关闭梯度，模型依然会计算并保存中间变量的梯度，导致**显存占用翻倍，且推理速度变慢**。

    **正确的做法是：**
    在推理时，必须配合使用上下文管理器来关闭梯度：
    ```python
    model.eval()
    with torch.no_grad():  # 或者使用更高效的 torch.inference_mode()
        output = model(input)
    ```

---

在`code\gpt2\train_gpt2.py`中的`sample_test()`函数把`model.eval() `注释掉，不影响结果（需要确认代码里没有`nn.Dropout()`）

## 4.3  model.to(device) vs x = x.to(device)



>[!NOTE]
> **`model.to(device)` 是“原地修改（In-place）”模型内部的参数和缓冲区；而 `x.to(device)` 是“创建一个新张量”并返回。**

### 4.3.1 model.to
在 PyTorch 中，`model`（即 `nn.Module` 的实例）本质上是一个**容器**，它内部包含了多个子模块、参数（`nn.Parameter`）和缓冲区（Buffer）。

调用 `model.to(device)` 时，底层实际执行的是：
1. **递归遍历**：它会递归地遍历模型内的每一个子模块。
2. **原地修改参数**：对于每一个参数和缓冲区，它会调用类似 `param.data = param.data.to(device)` 的操作。
3. **返回自身**：`nn.Module.to()` 方法最终返回的是 `self`（即模型对象本身）。

>[!IMPORTANT]
>+ **结论**：模型**内部引用的参数张量**的设备属性被**原地（in-place）** 改变了，但是对象本身的内存地址没有变，所以不需要重新赋值。(`self`指向的内存地址没变)
>+ 这里需要区分两个关键概念： `Python 对象的内存地址` 和 `张量底层数据的物理存储位置`
>    + Python 对象层（永远在 CPU 内存中）： 
>       + `model` 是一个 `nn.Module` 的 Python 对象。
>       + Python 解释器运行在 CPU 上，它管理的所有对象（包括 `nn.Module` 本身，以及它内部维护的存放参数的字典 `_parameters`）都**永远分配在 CPU 的系统内存（RAM）中**。
>       + “内存地址不变”（即 `id(model)` 不变），指的是这个 **Python 外壳对象**在 CPU 内存中的地址没有变。
>+ **C++ 底层数据层（可以在 CPU 或 GPU）**：
>   + `nn.Module` 内部包含的 `nn.Parameter` 本质上是 `torch.Tensor`。
>   + `Tensor` 在 Python 层只是一个“句柄（Handle）”，它内部包含一个指针（`data_ptr`），指向 C++ 底层实际存储数据的内存块。
>   + 当调用 `model.to('cuda')` 时，底层发生的是：
>       + 在 GPU 显存中分配一块新空间。
>       + 把数据从 CPU 拷贝到 GPU。
>       + **修改 Tensor 句柄内部的 `data_ptr` 指针**，让它指向 GPU 上的新地址。

----

### 4.3.2 tensor.to

>[!NOTE]
>`x = x.to(device)` 需要重新赋值

对于张量（`torch.Tensor`），PyTorch 的设计哲学是**元数据不可变**。张量的 `device`、`dtype`、`shape` 等元数据一旦确定，就不能被原地修改。

当调用 `x.to(device)` 时，底层实际执行的是：
1. 如果 `x` 已经在目标设备上，为了性能优化，它会直接返回 `x` 本身。
2. 如果 `x` 不在目标设备上（比如从 CPU 到 GPU），它会在目标设备上**分配一块全新的显存/内存**。
   1. **数据拷贝**：将原张量的数据拷贝到新分配的内存中。
   2. **返回新对象**：生成并返回一个**全新的张量对象**，原来的张量 `x` 依然留在原设备上，没有任何改变。


为什么这里不通过**修改 Tensor 句柄内部的 `data_ptr` 指针**，让它指向 GPU 上的新地址，来实现`x`的移动？
+ `Tensor`的结构:
  + Tensor（张量句柄）：包含形状（shape）、步长（stride）、偏移量（offset）等元数据。
  + TensorImpl（实现细节）：`Tensor` 指向它。
  + Storage（存储块）：`TensorImpl` 指向它。真正的 `data_ptr`（指向物理内存的指针）是保存在 Storage 里的
+ 如果在`to`的时候直接改了 `data_ptr`，
  ```python 
    # 例一： 视图（View）与内存共享彻底崩溃
     x = torch.randn(10, 10)      # x 在 CPU
     y = x.view(100)              # y 是 x 的视图，x 和 y 共享同一个 CPU Storage
     x = x.to('cuda')             # 假设这里直接修改了 x 的 data_ptr 指向 GPU
     
     # 如果直接修改 x 的底层指针
     # 则 y 的底层依然指向原来的 CPU Storage。
     # 则为了节省内存，PyTorch 把原来的 CPU Storage 释放了，y 瞬间变成了野指针（Dangling Pointer），程序直接崩溃。

     # 例二： 自动求导（Autograd）计算图断裂
     x = torch.randn(10, requires_grad=True)
     y = x * 2
     z = y.sum()
    # 此时计算图是：z -> y -> x
    # 如果直接修改了 x 的底层指针
    # 当执行 z.backward() 时，Autograd 引擎去计算 x 的梯度，发现 x 的底层指针已经指向了 GPU，而梯度累加器（Gradient Accumulator）还在 CPU 上，或者计算图的拓扑结构因为指针的突变而无法对齐，反向传播直接报错或计算出完全错误的梯度。
  ```

### 4.3.3 Module.to的底层实现

PyTorch 的设计哲学是：**张量的元数据（Device, Dtype）是不可变的（Immutable）**。
+ 因此`Tensor`要挪，必须创建一个新张量
+ 而`model`是原地操作，是因为`model`只是那些张量的封装，本身这个壳的指针是不变的
  + [文档：torch.Tensor/torch.Tensor.to](https://docs.pytorch.org/docs/2.15/generated/torch.Tensor.to.html#torch-tensor-to)
  + [文档：Module.to()](https://docs.pytorch.org/docs/2.15/generated/torch.nn.Module.html#torch.nn.Module.to)
+ [源码：torch/nn/modules/module.py-> to()](https://github.com/pytorch/pytorch/blob/v2.15.0/torch/nn/modules/module.py#L1259)
  + 需要看旧一点的torch版本：<https://github.com/pytorch/pytorch/blob/0c455332e8ca7b3c426b7eb95b696eef7bedee47/torch/nn/modules/module.py#L385>
  + 有以下关键内容：
   ```python
      # https://github.com/pytorch/pytorch/blob/0c455332e8ca7b3c426b7eb95b696eef7bedee47/torch/nn/modules/module.py#L573
      def to(self, *args, **kwargs):
          # 1. 解析 device, dtype, non_blocking 等参数
          device, dtype, non_blocking, convert_to_format = torch._C._nn._parse_to(*args, **kwargs)

          # 2. 定义一个闭包函数 convert，它的作用就是调用张量的 .to() 方法
          def convert(t):
              if convert_to_format is not None and t.dim() in (4, 5):
                  # 处理内存格式（如 channels_last），这里省略
                  return t.to(device, dtype if t.is_floating_point() else None, non_blocking, memory_format=convert_to_format)
              # 核心：调用底层张量的 to()，返回一个新的张量/参数
              return t.to(device, dtype if t.is_floating_point() else None, non_blocking)

          # 3. 将 convert 函数传递给核心方法 _apply
          return self._apply(convert)
      # https://github.com/pytorch/pytorch/blob/0c455332e8ca7b3c426b7eb95b696eef7bedee47/torch/nn/modules/module.py#L385
      def _apply(self, fn, recurse=True):
        # 1. 递归处理子模块 (Children)
        if recurse:
            for module in self.children():
                module._apply(fn, recurse)
        ...
        # 2. 核心：遍历并替换自身的 Parameters (参数)
        for key, param in self._parameters.items():
            if param is not None:
                # 调用传入的 fn (即上面的 convert 函数)
                # param.to(...) 会在 GPU 上创建一个新张量，并返回
                param_applied = fn(param)
                
                # 【关键代码】：将字典中的旧引用，替换为 fn 返回的新引用！
                # 如果返回的不是 Parameter，还需要重新包装一下
                if param_applied is not param:
                    self._parameters[key] = nn.Parameter(param_applied, requires_grad=param.requires_grad)
                    
        # 3. 核心：遍历并替换自身的 Buffers (缓冲区，如 BatchNorm 的 running_mean)
        for key, buf in self._buffers.items():
            if buf is not None:
                buf_applied = fn(buf)
                # 【关键代码】：同样，替换字典中的引用
                if buf_applied is not buf:
                    self._buffers[key] = buf_applied

        # 4. 返回自身 (self)
        return self
   ```

### 4.3.4 总结和延伸
* **为什么 `x = x.to(device)` 需要赋值？**
  + 因为对于普通张量 `x`，PyTorch 没有类似 `_apply` 这样的容器机制去替换它的底层引用。`x.to()` 只能返回一个新对象，如果您不写 `x = ...`，变量 `x` 在 Python 命名空间里依然绑定着那个旧的 CPU 张量。

* **为什么 `model.to(device)` 不需要赋值？**
  + 因为 `model.to()` 最终调用了 `_apply()`。`_apply()` 在内部通过 `self._parameters[key] = ...` **原地修改了模型内部字典的引用**。
  并且请注意 `_apply()` 的最后一行：**`return self`**。
  它返回的是模型对象本身。所以 `model = model.to(device)` 实际上等同于 `model = model`，毫无意义。

*  这里存在一个**致命的性能瓶颈**：
   + `_apply` 是**串行、逐个参数**调用 `fn(param)` 的。
     对于一个 7B 的 LLM，有几千个 `nn.Parameter`。这意味着 `model.to('cuda')` 会触发**几千次**独立的 CPU 到 GPU 的内存拷贝（PCIe 传输）。
     这种细粒度的拷贝不仅慢，而且在拷贝期间，GPU 的计算单元是闲置的。
   + **这就是为什么在 LLM 领域，会极力避免使用原生的 `model.to()`：**
       1. **HuggingFace 的 `device_map="auto"`**：它在底层完全绕过了 `nn.Module.to()`。它使用 `init_empty_weights` 初始化空壳模型，然后直接读取 Safetensors 权重文件，**按层（Layer）甚至按张量分块（Shard）**，以最大的块（Chunk）一次性通过 DMA（直接内存访问）搬运到 GPU 上，将 PCIe 的带宽利用率榨干。
       2. **DeepSpeed/Megatron**：在分布式初始化时，也是直接在目标设备上分配内存并加载分片权重，绝不会在 CPU 上实例化完整模型后再调用 `to()`。

几个容易造成误区的关键点(直接用llm把source里的说明部分全都翻译一下。。)
+ The `input` is expected to contain the unnormalized logits for each class (which do `not` need to be positive or sum to 1, in general). `input` has to be a Tensor of size $(C)$ for unbatched input, $(minibatch, C)$ or $(minibatch, C, d_1, d_2, ..., d_K)$ with $K \geq 1$ for the `K`-dimensional case. The last being useful for higher dimension inputs, such as computing cross entropy loss per-pixel for 2D images.
  + `input`: 包含对每个类的没有归一化过的`logits`, 不是必须保证和为1，即：不需要额外提前进行softmax归一化；
  + 对于`unbatched`的输入，`input`必须是$(C)$的张量
  + 对于`batch`的输入，`input`必须是$(minibatch, C)$或$(minibatch, C, d_1, d_2, ..., d_K)$shape的张量，对于后者， $K \geq 1$是针对于`K`维的情况
  + 这里 $C = \text{number of classes}$, $N =\text{batch size}$
+ `target`（目标标签）应包含以下两种形式之一：
  - `Class indices`，取值范围为 $[0, C)$，其中 $C$ 为类别总数；如果指定了 `ignore_index`，该损失函数也会接受此索引值（该索引不一定在正常的类别取值范围内）。当未进行归约（即 `reduction` 设置为 `'none'`）时，此情况下的损失计算公式如下：

    $$
    \ell(x, y) = L = \{l_1,\dots,l_N\}^\top, \quad l_n = - w_{y_n} \log \frac{\exp(x_{n,y_n})}{\sum_{c=1}^C \exp(x_{n,c})} \cdot \mathbb{1}\{y_n \neq \text{ignore\_index}\}
    $$

    其中，$x$ 为输入，$y$ 为目标标签，$w$ 为权重，$C$ 为类别总数。如果 `reduction` 参数不为 `'none'`（默认为 `'mean'`），
    
    标记 $x_{n,y_n}$中  
    
    **$n$ (样本索引)** 代表展平（flatten）后的第 $n$ 个样本。如果输入是 2D 的 `(batch_size, C)`，那么 $n \in [0, \text{batch\_size}-1]$；如果是处理图像分割或序列的 3D/4D 张量，$n$ 则跨越了 batch 维度以及空间维度 $d_1, \dots, d_k$.  
    
    **$y_n$ (真实类别索引)**代表第 $n$ 个样本的**真实标签（Ground Truth）** 所对应的类别下标。

    $x_{n,y_n}$ 表示：**对于第 $n$ 个样本，模型在“它真实的正确类别 $y_n$”上输出的原始预测得分（logit）。**

    $$
    \ell(x, y) = \begin{cases}
        \sum_{n=1}^N \frac{1}{\sum_{n=1}^N w_{y_n} \cdot \mathbb{1}\{y_n \neq \text{ignore\_index}\}} l_n, & \text{if reduction} = \text{'mean'};\\
        \sum_{n=1}^N l_n, & \text{if reduction} = \text{'sum'}.
    \end{cases}
    $$

    需要注意的是，这种情况在数学上等价于先对输入应用 `LogSoftmax`，然后再计算 `NLLLoss`。 即
    ```python
      counts = logits.exp()
      prob = counts/counts.sum(1,keepdim = True)
      loss = - prob[torch.arange(32), Y].log().mean()
    ```

  - `每个类别的概率`；当小批量（minibatch）中的每个样本需要包含多个类别的标签信息时（例如混合标签 blended labels、标签平滑 label smoothing 等场景），这种形式非常有用。当未进行归约（即 `reduction` 设置为 `'none'`）时，此情况下的损失计算公式如下：

    $$
    \ell(x, y) = L = \{l_1,\dots,l_N\}^\top, \quad l_n = - \sum_{c=1}^C w_c \log \frac{\exp(x_{n,c})}{\sum_{i=1}^C \exp(x_{n,i})} y_{n,c}
    $$

    其中，$x$ 为输入，$y$ 为目标标签，$w$ 为权重，$C$ 为类别总数。如果 `reduction` 参数不为 `'none'`（默认为 `'mean'`），则：

    $$
    \ell(x, y) = \begin{cases}
        \frac{\sum_{n=1}^N l_n}{N}, & \text{if reduction} = \text{'mean'};\\
        \sum_{n=1}^N l_n, & \text{if reduction} = \text{'sum'}.
    \end{cases}
    $$

  **注意**：通常情况下，当 `target` 采用**类别索引**（即第一种情况）时，该损失函数的计算性能更好，因为这种形式允许底层进行高度优化的计算。只有当“每个样本只能属于单一类别”这一假设过于严苛，无法满足实际需求时，才建议将 `target` 设置为类别概率分布。


----



1.  **Softmax 概率计算**：$\frac{\exp(x_{n,y_n})}{\sum_{c=1}^C \exp(x_{n,c})}$
    *   这就是标准的 Softmax 公式。分子是真实类别的 logit 指数，分母是所有 $C$ 个类别 logit 指数之和。计算结果就是模型预测第 $n$ 个样本属于真实类别 $y_n$ 的**概率 $p$**。
2.  **负对数似然 (NLL)**：$-\log(\dots)$
    *   对概率取对数并加负号。预测概率 $p$ 越接近 1，$\log(p)$ 越接近 0，Loss 越小；$p$ 越接近 0，Loss 越大。
3.  **类别权重**：$w_{y_n}$
    *   对应 PyTorch 中的 `weight` 参数。$w_{y_n}$ 表示真实类别 $y_n$ 的权重。主要用于处理**类别不平衡**问题（例如长尾分布），给少数类更大的权重。
4.  **忽略掩码**：$\mathbb{1}\{y_n \not= \text{ignore\_index}\}$
    *   这是一个指示函数。如果真实标签 $y_n$ 等于 `ignore_index`，则该项为 0，该样本的 loss 为 0，**不参与反向传播的梯度计算**。

---

映射到 LLM 的 **Next-token prediction (自回归语言模型)** 任务中

在 LLM 的 LM Head 输出后，计算 Loss 时：
*   **$C$ (类别数)**：等于 **词表大小 (Vocab Size)**，比如 32000 或 128000。
*   **$N$ (样本总数)**：等于 `batch_size * seq_len`（如果是 causal LM，通常还会减去 1，因为输入和标签有错位）。也就是当前 batch 中**所有需要预测的 token 总数**。
*   **$y_n$ (真实标签)**：第 $n$ 个位置上的**目标 token ID**（即输入序列往后错位一位的 token）。
*   **$x_{n, y_n}$**：模型在第 $n$ 个位置，预测出**真实目标 token ID** 的那个 logit 值。
*   **$\text{ignore\_index}$**：通常被设置为 **`pad_token_id`**。在 LLM 训练时，一个 batch 内的序列长度不一，短序列会用 pad token 补齐。设置 `ignore_index=pad_token_id` 后，模型在计算 loss 时就会**自动忽略所有 padding 位置**，只计算有效 token 的交叉熵。

---

数值稳定性 (Numerical Stability)

PyTorch 底层**并没有**直接按这个公式算，而是利用了 **LogSumExp trick** 进行了数学等价变换：
$$ -\log \frac{\exp(x_{n,y_n})}{\sum_{c} \exp(x_{n,c})} = -x_{n,y_n} + \log \sum_{c} \exp(x_{n,c}) $$
在计算 $\log \sum \exp(x_{n,c})$ 时，PyTorch 会先减去一个最大值 $m = \max_c(x_{n,c})$ 来保证指数运算的数值稳定性：
$$ \log \sum_{c} \exp(x_{n,c}) = m + \log \sum_{c} \exp(x_{n,c} - m) $$
